## State of use

Krish has read the morning view and wants a quick follow-up without translating trading language or searching through the page. On mobile he may be one-handed. The first useful words should begin appearing immediately.

## User and action

One signed-in investor asks a question about today's COMPOUND view, reads a plain answer, checks which data supported it and asks another question if needed.

## Governing rule

COMPOUND answers only from authorised COMPOUND evidence available to the signed-in user. It shows the data time and the evidence used. If the data cannot support an answer, it says so plainly. It never invents current market facts, hides old or missing data, reads Control Center records or places a trade.

## Interaction rule

- The question and answer sit on a dedicated Ask surface, not inside a cramped dashboard card.
- Suggested questions provide the fast path. Free text remains available.
- The answer appears where the question was asked and streams as it is produced.
- Evidence comes from the retrieved COMPOUND records, not model-written citations.
- The user's question persists with the answer in the `compound` schema.
- A model or network failure leaves the question intact and offers one clear retry.

## Zero-context language contract

- Use full names before ticker symbols.
- Explain any unavoidable finance term in the same sentence.
- State the answer first, then the evidence and what would change it.
- Separate what the data shows from what remains uncertain.
- Never use AI, assistant, copilot, analysis engine or similar product language on the surface.

## Data and safety boundary

1. The browser sends the signed-in user's question and Supabase access token to the COMPOUND Edge Function.
2. The function uses that user's token with the public Supabase client key so RLS remains in force.
3. Retrieval targets only the `compound` schema and selects the minimum snapshot, evidence and investment rows needed for the question.
4. The LLM credential exists only as a dedicated Edge Function secret.
5. The model receives a bounded evidence packet. It receives no Control Center data and no database access.
6. Evidence labels and freshness are rendered from retrieved records, not generated by the model.

## Required states

- Answer ready.
- Answer streaming.
- No relevant evidence.
- Data too old for a current answer.
- Model or network unavailable with the question preserved.
- Long question and long company name.
- Attempt to request Control Center data or override the evidence boundary.
